# NUMBUS Branding

Telegram-бот, который оформляет фото в фирменном стиле клиента: логотип и хештег
с адаптивным цветом, обложки для ленты и сторис IG/TG. Один бот обслуживает много
брендов; доступ — по инвайт-кодам.

## Файлы

| Файл | Что внутри |
|---|---|
| `bot.py` | Диалоги: меню, мастер бренд-кита, создание постов, команда, админ-команды |
| `render.py` | Движок рендера (перенесён из ÖMANKÖ, параметры — из бренд-кита) |
| `db.py` | Хранилище SQLite: бренды, участники, ассеты, коды, статистика; тарифы — `PLANS` |
| `texts.py` | Все тексты интерфейса на русском и английском |
| `Dockerfile`, `requirements.txt` | Сборка для Railway (шрифты скачиваются при сборке) |

## Запуск

1. **Бот.** В @BotFather: `/newbot` → получить токен. Там же `/setcommands`:
   ```
   start - Меню
   cancel - Отменить
   ```
2. **Репозиторий.** Новый приватный репозиторий `numbus-branding` на GitHub →
   Add file → Upload files → перетащить все файлы разом.
3. **Railway.** New Project → Deploy from GitHub repo → `numbus-branding`.
4. **Переменные** (Variables):
   - `BOT_TOKEN` — токен от BotFather
   - `ADMIN_IDS` — твой Telegram ID (несколько — через запятую)
   - `SUPPORT_CONTACT` — куда писать клиентам, например `@aleskan`
   - `RENDER_WORKERS` — необязательно, по умолчанию 2 (сколько фото рендерится одновременно)
5. **Volume — обязательно.** Settings → Volumes → Add Volume, mount path любой
   (например `/data`). Без него база обнуляется при каждом деплое.
   Проверка: `/brands` покажет «Хранилище: постоянное».

## Админ-команды (видны только ADMIN_IDS)

| Команда | Что делает |
|---|---|
| `/newcode [тариф] [дней] [использований]` | Создать инвайт-код. По умолчанию `pilot 30 1`. Ответ содержит готовый текст для клиента |
| `/codes` | Последние 30 кодов и сколько раз использованы |
| `/brands` | Все бренды: тариф, срок, участники, фото за месяц |
| `/extend <id> <дней> [тариф]` | Продлить бренд и при желании сменить тариф |
| `/myid` | Узнать свой Telegram ID |

Тарифы и лимиты — словарь `PLANS` в `db.py`.
