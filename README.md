# NUMBUS Branding

Telegram-бот, который оформляет фото в фирменном стиле клиента. Клиент один раз
собирает стиль — за пару минут прямо в чате, тонко — в редакторе (Telegram Mini App).
Дальше он присылает фото с подписью и получает готовые файлы для ленты, сторис и
каруселей. Один бот обслуживает много брендов; доступ — по коду или по заявке.

## Запуск

### 1. Бот
@BotFather → `/newbot` → токен. Имя, описание, команды и кнопку «Редактор» бот
выставляет сам при каждом запуске. Вручную в BotFather — только аватар (`/setuserpic`).

### 2а. Railway
1. New Project → Deploy from GitHub repo. Railway соберёт образ по `Dockerfile`
   (так задано в `railway.toml`; там же проверка живости `/healthz` и перезапуск при сбое).
2. Сервис бота → Settings → Deploy → **Region: EU West (Amsterdam)** — ближе всего к
   клиентам в России и к серверам Telegram. Регион выбирайте до создания диска.
3. Settings → Networking → **Generate Domain** (адрес редактора бот возьмёт из
   `RAILWAY_PUBLIC_DOMAIN`; свой домен — переменная `WEBAPP_URL`).
4. **Диск (Volume):** правый клик по пустому месту холста проекта (или ⌘K / Ctrl+K) →
   **Volume** → выберите сервис бота → Mount path **`/data`**. **Без диска база обнуляется
   при каждом деплое.** Railway сам передаст боту путь диска (`RAILWAY_VOLUME_MOUNT_PATH`),
   задавать `DATA_DIR` не нужно.
5. Variables → **Raw Editor** → вставьте строки из `env.example.txt` (без «#» в начале),
   замените значения → Update Variables.
6. Проверка: адрес `https://<домен>/healthz` отвечает `"persistent": true`, а `/admin` в боте —
   «Хранилище: постоянное». `false` / «ВРЕМЕННОЕ» — диск не подключён: данные пропадут при деплое.

Шрифты каталога сборка скачивает с GitHub (`scripts/get_fonts.sh`). Чтобы не зависеть от сети,
можно загрузить в репозиторий папку `fonts/` со всеми 16 файлами `.ttf` — сборка возьмёт их,
`Dockerfile` менять не нужно.

### 2б. Свой сервер в России (Selectel, Timeweb Cloud, Yandex Cloud, VK Cloud)
Нужен сервер с Docker (2 ГБ памяти хватит) и домен, A-запись которого указывает на сервер.
```
git clone https://github.com/Alexan2024/numbus_branding.git && cd numbus_branding
cp env.example.txt .env     # заполнить BOT_TOKEN, ADMIN_IDS, DOMAIN, WEBAPP_URL
docker compose up -d --build
docker compose logs -f bot  # «Редактор: порт 8080…», затем опрос Telegram
```
Caddy сам получит HTTPS-сертификат. База, копии и черновики лежат в `./data`.
Обновление: `git pull && docker compose up -d --build`.

**Telegram из России.** Если `api.telegram.org` с сервера отвечает медленно или
не отвечает, бот не падает: редактор работает, бот повторяет подключение и пишет в
лог «Нет связи с Telegram». Решение — `TG_PROXY` (SOCKS5 или HTTP-прокси вне РФ)
или `TG_API_URL` (свой сервер Bot API). Состояние видно по адресу `/healthz`:
`telegram` — связь с Telegram, `persistent` — лежит ли база на постоянном диске.

Проверка после запуска: `/admin` покажет «Хранилище: постоянное», способ копий и адрес редактора.

### Переменные окружения

| Переменная | Зачем |
|---|---|
| `BOT_TOKEN` | Токен бота — обязательно |
| `ADMIN_IDS` | Telegram ID администраторов через запятую (свой ID — команда `/myid`) |
| `SUPPORT_CONTACT` | Куда писать клиентам, например `@aleskan` |
| `WEBAPP_URL` | Адрес редактора, `https://…`. На Railway можно не задавать |
| `DATA_DIR` | Папка для базы, копий и черновиков. По умолчанию — диск Railway или `/data`. Постоянной считается, только если лежит на подключённом диске |
| `TG_PROXY` | `socks5://user:pass@host:1080` или `http://host:3128` — если Telegram режут |
| `TG_API_URL` | Свой сервер Bot API (`telegram-bot-api`), например `http://10.0.0.5:8081` |
| `BOT_TZ` | Часовой пояс дат и времени копий, по умолчанию `Europe/Moscow` |
| `BACKUP_HOUR` | Час ежедневной копии (0–23, просто число), по умолчанию 4 |
| `BACKUP_S3_ENDPOINT`, `_BUCKET`, `_KEY`, `_SECRET`, `_REGION`, `_PREFIX` | Хранилище для копий (см. ниже) |
| `BACKUP_TO_TELEGRAM` | `true` — присылать копию админам, если S3 не настроен |
| `PILOT_DAYS` | Срок доступа при одобрении заявки, по умолчанию 30 |
| `PRIVACY_URL` | Ссылка на политику обработки данных — кнопка в настройках |
| `RENDER_WORKERS` | Сколько фото рендерить одновременно, по умолчанию 2. На пилоте — `1`: меньше памяти |
| `MALLOC_ARENA_MAX` | `2` — память после тяжёлых альбомов возвращается системе (замер: −40% в простое). Уже задана в `Dockerfile` |
| `VISION_PROVIDER` | Стиль по образцу: формат API модели — `anthropic` или `openai` (любой OpenAI-совместимый с картинками). Можно не задавать: ключ `sk-ant-…` сам выбирает `anthropic` |
| `VISION_API_KEY`, `VISION_MODEL` | Ключ и модель с поддержкой изображений. Для Anthropic модель по умолчанию — `claude-sonnet-5-5`. Без ключа кнопки «Стиль по образцу» в меню нет |
| `VISION_BASE_URL` | Адрес API, если не стандартный (свой шлюз провайдера) |
| `VISION_TIMEOUT` | Сколько ждать ответа модели, секунд, по умолчанию 90 (`90s` тоже понимается) |
| `VISION_THINKING` | `off` (по умолчанию) — Sonnet 5.5 отвечает без предварительного размышления; `on` — с ним (дороже) |
| `SAMPLE_PER_BRAND_DAY` | Разборов «Стиля по образцу» на бренд в сутки (по `BOT_TZ`), по умолчанию 5 |
| `SAMPLE_PER_DAY` | Разборов на весь бот в сутки, по умолчанию 40 |
| `VISION_BUDGET_USD` | Бюджет на модель за календарный месяц, $, по умолчанию 3.0: на 80% — одно предупреждение админам, на 100% — разбор выключен до 1-го числа. Траты видны в `/admin` |

Пустое или неверное значение (`BACKUP_HOUR=`, `BACKUP_S3_REGION=`) не роняет бота: берётся значение
по умолчанию, в логе — предупреждение. Ненужную переменную лучше удалить целиком.

## Как клиент начинает

1. **Доступ.** Код `NB-XXXX-XXXX` (`/newcode`) или кнопка «Запросить доступ»: клиент
   присылает ссылку на канал, админам приходит заявка с кнопками «Открыть доступ» и
   «Отклонить». Одобрение создаёт бренд на пилот (`PILOT_DAYS`).
2. **Настройка стиля — 4 шага в чате:** название → логотип (PNG, SVG или PDF; фон
   убирается сам) → фирменный цвет из логотипа → фото из ленты клиента, на котором бот
   показывает три стиля. Выбранный становится стилем по умолчанию.
3. Дальше — посты. Тонкая настройка — кнопка «Редактор стиля» или `/desktop` на компьютере.

Если бот перезапустили посреди настройки, она продолжится с того же шага.

## Как делается пост

Фото (одно или альбомом до 30) с подписью. Первая строка — заголовок, после пустой
строки — подзаголовок, `#слово` — рубрика (первый хештег; остальные попадут в текст поста).
Переносы строк из подписи сохраняются. **Жирный текст** в подписи — это выделение: шаблон
рисует его стилем выделения слоя (цвет, вес, шрифт). То же можно набрать звёздочками:
`*₽1 трлн*`; сама звёздочка — `\*`. Рубрика с пробелами: `#Vive_la_différence` — если у слоя
рубрики включено «Без # и _», в кадре будет «Vive la différence».
Бот отвечает превью с пультом:

- стиль, формат (4:5, 3:4, 1:1, 3:2, 16:9, 1.91:1, 9:16, как в оригинале), рубрика, светлее / темнее, текст;
- масштаб фото «− ×1.25 +» (до ×3) — для каждого кадра карусели свой;
- в карусели — листание кадров «‹ 1 / 3 ›»;
- если фото обрезается (кадром или рамкой фото), бот пишет, сколько уходит, и даёт выбрать
  часть: верх / центр / низ (или лево / центр / право);
- «Получить файлы» — JPG без сжатия альбомами по 10, следом текст поста для копирования
  (через типограф); «Альбом для канала» — те же фото с подписью, чтобы переслать в канал.

Черновик хранится на диске сутки: перезапуск бота его не теряет. Если лимит фото
кончается, бот предлагает сделать сколько осталось.

## Стиль и шаблоны

**Бренд-кит:** название, два логотипа, палитра из пяти цветов с ролями (светлый,
тёмный, акцент, два дополнительных), до трёх своих шрифтов, хештеги, фото для превью.

**Шаблон** — стопка слоёв для ленты и (по желанию) сторис: логотип, текст (заголовок,
подзаголовок, рубрика, счётчик «2 / 8», надпись), фигура или рамка, градиент,
затемнение, графика из макета, **фото в рамке**. У каждого слоя — правило кадров карусели: на всех,
только на обложке или кроме обложки. В стартовых стилях заголовок и рубрика — только
на обложке. Счётчик на одиночном фото не рисуется.

**Текст:** типограф (кавычки «ёлочки», тире, неразрывные пробелы после предлогов,
между числом и ₽), предел строк — длинный заголовок сначала уменьшается, потом
обрезается многоточием, и бот об этом предупреждает. Знаки, которых нет в шрифте (₽ в
Playfair, № в Jost, кириллица в латинском шрифте), рисуются Inter — и на сервере, и в
редакторе.

**Фото в рамке:** фото поста встаёт в прямоугольник (или с полями от края) со скруглением,
своей точкой фокуса и масштабом до ×4; фон кадра вокруг — цвет слоя. Так делаются карточки
с фото-врезкой, текстовый блок над фото, фото со сдвигом и затемнением сбоку.

**Выделение и поток:** у текстового слоя — стиль выделения для `*…*` (цвет, вес, свой
шрифт: жирная часть заголовка, жёлтые суммы). «Под слоем» ставит слой под другим с
отступом — подзаголовок не наезжает на заголовок любой длины.

**Градиент** может начинаться не от края («Начало от края»): до начала — сплошной цвет.

**Файл:** фото переводится в sRGB (снимки iPhone — Display P3), JPEG 4:4:4 с
профилем sRGB, 1920 px по ширине для ленты.

## Стиль по образцу

В меню — «Стиль по образцу» (владелец и дизайнер, после настройки стиля, если задан `VISION_API_KEY` и тариф активен). Клиент присылает
свой фирменный пост картинкой или файлом, через 20–40 секунд бот присылает «образец / шаблон»
рядом и кнопки «Сохранить стиль», «Собрать ещё раз», «Другой образец». Сохранённый стиль
становится выбранным, формат — как у образца.

Как устроено (`sample.py`): модель с картинками описывает макет в JSON (фото на весь кадр или
в рамке, фон, текстовые блоки по строкам с ролями, выделенные слова, плашки, логотип,
градиенты, фигуры). Точность — локально: маска букв снимается с образца, движок рисует тот же
текст шрифтами каталога и своими шрифтами бренда, кегль, интерлиньяж и место подбираются по
маске, шрифт — по лучшему совпадению. Рамка фото и плашки уточняются по краям, цвета — по
пикселям. Логотип — логотип бренда, в рамке логотипа с образца. Блоки, которые совпали слабо,
бот называет в подписи («Проверьте в редакторе: …»). Фото для превью — из рамки образца или
сам образец со стёртым текстом.

**Деньги и сбои.** Каждый разбор — платный вызов модели (Sonnet 5.5 — около $0,02). Лимиты:
`SAMPLE_PER_BRAND_DAY`, `SAMPLE_PER_DAY` и месячный `VISION_BUDGET_USD` (`quota.py`, таблицы
`vision_calls` и `vision_flags` в той же базе). «Собрать ещё раз» и повтор того же образца собираются
из сохранённого разбора — без нового вызова. Если сервис модели не отвечает (нет денег на балансе,
перегрузка, сеть), клиент видит «Сервис разбора сейчас недоступен», админам приходит одно оповещение
с кодом ошибки, бот продолжает ждать образец. Вызов модели идёт вне очереди рендера — посты других
клиентов в это время не ждут.

Образец уходит провайдеру модели (Anthropic, США) — учтите это в политике обработки данных.

## Редактор

- **Простой режим** (по умолчанию для владельца): готовые стили на своём фото —
  нажал и примерил; логотип (где, размер, цвет); шрифты парой; рубрика; затемнение;
  цвета бренда и «Взять из логотипа».
- **Режим дизайнера** (по умолчанию для роли «дизайнер»): слои и все их свойства,
  тень текста, предел строк, правило кадров, безопасные зоны сторис и обрез в сетке
  профиля 3:4, притяжение к полям 6% и к центру, импорт макетов (PSD, AI, PDF, Figma)
  и «С нуля» в листе нового шаблона.

Над картинкой: лента / сторис, «Отменить» / «Вернуть», формат, «Обложка» / «Кадр 2»,
своё фото. «Проверить итог» — рендер сервера, ровно то, что выдаст бот.
Клавиши на компьютере: стрелки (с Shift — на 10 px), ⌘Z / ⌘⇧Z, ⌘S, Delete, Esc.

## Команда и роли

У каждого бренда своя ссылка-приглашение («Команда»). Роли:

| Роль | Что может |
|---|---|
| Владелец | Всё: стиль, команда, продление, удаление бренда |
| Дизайнер | Редактор стиля и шаблоны, посты. Без команды и тарифа |
| Участник | Только посты |

Кнопку «Редактор» у поля ввода бот показывает только владельцам и дизайнерам.

## Тарифы и лимиты

Подписка — корневой бренд (по коду или заявке) и привязанные к нему бренды. Тариф,
срок, лимит фото и людей — общие на подписку. Лимит фото считается за **30-дневный
период от даты активации** (а не за календарный месяц); продление после перерыва
начинает новый период.

| Тариф | Фото за период | Людей | Брендов |
|---|---|---|---|
| Pilot | 500 | 5 | 1 |
| Solo | 150 | 1 | 1 |
| Media | 1000 | 5 | 1 |
| Studio | 5000 | 20 | 10 |

## Аналитика пилота

Каждый шаг пишется в таблицу `analytics`: старт, заявка, код, шаги настройки, выбор
стиля, черновик, превью, выдача файлов (сколько фото, формат, сколько нажатий пульта,
сколько секунд от фото до файлов), открытие редактора, сохранение шаблона, ошибки.
`/stats [дней]` показывает метрики пилота: активацию (файлы в первые сутки), время до
первых файлов, долю превью, дошедших до файлов, медиану нажатий пульта, платящих и
регулярность по брендам. В админ-панели — поиск бренда и карточка клиента.

## Копии базы и оповещения

Каждый день в `BACKUP_HOUR` бот делает горячую копию SQLite (без остановки), сжимает
её и хранит 7 последних в `DATA_DIR/backups`. Если заданы `BACKUP_S3_*` — копия уходит
в хранилище (подпись AWS SigV4, подходит Selectel, Yandex Object Storage, Timeweb, VK
Cloud); если нет и `BACKUP_TO_TELEGRAM=true` — приходит админам документом. Вручную —
`/backup` или «Копия базы» в админ-панели.

Восстановление из копии:
1. Остановите бота (свой сервер: `docker compose stop bot`).
2. Распакуйте копию: `gunzip numbus-ДАТА.db.gz` → `numbus-ДАТА.db`.
3. В папке данных (`DATA_DIR`: `/data` на Railway, `./data` на своём сервере) **удалите
   `numbus.db`, `numbus.db-wal` и `numbus.db-shm`**, затем положите копию под именем `numbus.db`.
   Если оставить старый `numbus.db-wal`, SQLite при запуске перенесёт в копию изменения из него —
   и вернётся не копия, а состояние до сбоя (проверено, см. `docs/CHANGES-v6.md`).
4. Запустите бота (`docker compose start bot`) и проверьте `/admin`.

На Railway к файлам диска из панели не добраться: восстановление делается в терминале
сервиса (`railway ssh` из Railway CLI) — лучше вместе с разработчиком.

Ошибки приходят админам в личку (одинаковые — не чаще раза в 10 минут), клиент видит
короткое сообщение без технических деталей. Ошибки редактора тоже: в логе — подробно,
в редакторе — «Не получилось. Попробуйте ещё раз.»

## Данные и безопасность

- В Telegram каждый запрос редактора подписан (`initData`), подпись старше суток не
  принимается. С компьютера — сессия по одноразовой ссылке из бота (15 минут), живёт
  7 дней; в базе хранится только хэш токена. «Выйти на всех компьютерах» — в настройках.
- Ограничение частоты: превью, загрузки, импорт и вход с компьютера. Адрес для лимита входа —
  последний в `X-Forwarded-For` (его дописывает прокси Railway или Caddy): подмена заголовка
  лимит не обходит.
- Размер запросов: файлы — до 60 МБ (загрузка и импорт), шрифты — до 10 МБ, вход с компьютера —
  до 4 КБ, остальное — до 1 МБ. Слишком большой запрос отклоняется до чтения.
- Всё из редактора проходит `spec.sanitize_spec`; SVG-логотипы очищаются от скриптов
  и внешних ссылок; картинки больше 100 Мп не открываются. Импорт PSD — холст до 16 Мп
  (4000 × 4000) и слои до 16 Мп (сборка слоёв берёт до ~2 ГБ памяти; импорты идут по одному);
  макеты PSD, PDF/AI, PNG и Figma — не выше 8000 px при ширине 1920 (до ~4:1).
- Графика, которую загрузили в редактор, но не сохранили в шаблоне, удаляется через сутки —
  не раньше: её мог только что загрузить другой участник команды.
- «Удалить бренд» и «Удалить мои данные» — в настройках бота: удаляются бренды,
  стили, файлы, участие в командах, статистика и сохранённые шаги диалога.

## Админ-команды (видны только ADMIN_IDS)

| Команда | Что делает |
|---|---|
| `/admin` | Панель: статистика, поиск бренда, заявки, копия базы, отладка, очистка чата |
| `/stats [дней]` | Метрики пилота |
| `/newcode [тариф] [дней] [использований]` | Код доступа. По умолчанию `pilot 30 1`, в ответе — текст для клиента |
| `/codes` | Последние коды и использования |
| `/brands` | Все бренды (больше 60 — файлом CSV) |
| `/extend <id> <дней> [тариф]` | Продлить бренд и при желании сменить тариф |
| `/backup` | Копия базы сейчас |
| `/myid` | Свой Telegram ID |

В «Отладке» можно переключить тариф своего бренда, сделать его истёкшим, продлить,
обнулить счётчик фото и посмотреть на бота глазами участника.
